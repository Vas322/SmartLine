# Backlog проекта Smartline

Незавершённые и планируемые задачи. Требуют продуктовой проработки (Head of Product) и/или технического плана (Architect) перед реализацией. Не являются готовыми к исполнению.

## 1. Детализация посещения по каждому пользователю
- **Суть:** предоставить детализированное представление посещений/активности для каждого пользователя (игрока) — расшифровка по конкретным заходам, волнам, сессиям.
- **Статус:** идея, не в работе.
- **Заметки:** опираться на существующие модели `Activity` / `Player`; не создавать новую архитектуру без необходимости; не дублировать данные.

## 2. Учёт исправлений времени начала волны, времени на волне, активности
- **Суть:** механизм ручных исправлений (корректировок) после парсинга сообщений:
  - время начала волны;
  - время, проведённое на волне;
  - активность (тип/объём).
- **Статус:** идея, не в работе.
- **Заметки:**
  - согласно PROJECT_RULES, авто-определение волн/фортов пока вне scope; расширение расписанием волн — отдельная задача;
  - исправления должны быть аудируемыми (кто и когда поправил, старое/новое значение);
  - необходимо уточнить у Head of Product: что именно правим, кто правит, как исправления влияют на расчёт оплачиваемой активности.

## 3. Возможность отправлять сообщения из веб в Telegram-группу
- **Суть:** отправка сообщений из веб-интерфейса Smartline в Telegram-группу клана (исходящее сообщение от бота/администратора).
- **Статус:** идея, не в работе.
- **Заметки:**
  - требует продуктовой проработки (кто может отправлять, в какую группу, формат, нужно ли подтверждение);
  - архитектурно: использовать уже настроенный Telegram Bot Token для исходящих (метод send_message по chat_id группы), не смешивать с парсингом входящих;
  - держать отдельный компонент/сервис для исходящих сообщений;
  - исходящие сообщения должны быть аудируемыми (кто отправил, когда, текст).
